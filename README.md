# GlowBattlePass

Боевой пропуск и аукцион с собственной целочисленной валютой. Без Vault и PlayerPoints. Основной API — Spigot 1.16.5, байткод Java 8. Используется только публичный Bukkit API без NMS. Совместимость с конкретными новыми версиями сервера требует проверки на этих версиях; она не подтверждена автоматически.

## Статус

Исходники подготовлены. По просьбе заказчика компиляция, сборка JAR и запуск тестов не выполнялись. Перед установкой на рабочий сервер необходимы сборка и проверка на тестовом сервере, включая меню, SQLite, рестарт и аукцион. Готовый JAR в репозиторий не включён.

## Установка

Нужен Maven 3.9+, JDK 17+ для сборки с `--release 8`; для сервера 1.16.5 — поддерживаемая им Java. Новым серверам нужна их собственная версия Java. Команда сборки из корня: `mvn clean verify`. Результат: `target/GlowBattlePass-1.0.0.jar`. Поместите JAR в `plugins` и перезапустите сервер. PlaceholderAPI 2.11.6+ необязателен. SQLite JDBC включается в JAR через Shade.

Сетевые источники зависимостей: `repo.maven.apache.org`, `hub.spigotmc.org`, `repo.extendedclip.com`. Используйте существующий checkout; отдельный Git worktree не требуется.

## Команды игроков

| Команда | Назначение |
| --- | --- |
| `/bp` | Главное меню |
| `/bp help` | Помощь |
| `/bp stats` | Уровень, опыт, задания и тип пропуска |
| `/bp open <меню>` | main, daily-quests, rewards, auction |
| `/bp open week <номер>` | Задания указанной недели |
| `/bp leaderboard [tier\|quests]` | Топ 10 |
| `/bp boosters` | Личные и глобальные бустеры |
| `/bp balance` | Баланс валюты БП |
| `/bp mail` | Забрать один предмет из почты |
| `/bpah` | Аукцион |
| `/bpah sell <цена>` | Продать весь стак в основной руке |
| `/bpah search <название>` | Поиск по материалу или имени предмета |
| `/bpah <ник>` | Лоты игрока |

В аукционе ЛКМ покупает лот, ПКМ снимает свой. Купленные, снятые и просроченные предметы попадают в почту. Выручка зачисляется продавцу, даже если он не в сети. Для получения предмета нужен пустой слот. Валюта не переводится между игроками отдельной командой.

## Администрирование

Право: `glowbattlepass.admin`, по умолчанию OP. Алиас `/bpadmin`.

| Команда | Назначение |
| --- | --- |
| `/bpa editor` | Визуальное создание и изменение заданий |
| `/bpa reload` | Перечитать конфигурацию и меню |
| `/bpa currency give <игрок> <количество>` | Выдать валюту |
| `/bpa currency take <игрок> <количество>` | Забрать валюту |
| `/bpa currency set <игрок> <количество>` | Установить баланс |
| `/bpa set pass <игрок> <free\|premium>` | Тип пропуска |
| `/bpa boosters add <игрок\|all> experience <процент> <часы> <цель>` | Добавить бустер опыта |
| `/bpa boosters clear <игрок\|all>` | Удалить бустеры указанной области |
| `/bpa reset quest <игрок> <неделя> <id>` | Сбросить квест, 0 означает ежедневный |
| `/bpa progress quest <игрок> <неделя> <id> <количество>` | Добавить прогресс |
| `/bpa progress daily quest <игрок> <id> <количество>` | Прогресс ежедневного задания |
| `/bpa refresh daily quests` | Сбросить ежедневный прогресс всем |
| `/bpa sync daily quests` | Передать текущую дату ежедневных заданий серверам прокси |
| `/bpa new season confirm` | Сбросить опыт, пропуска, задания, бустеры и отметки наград |
| `/bpa material <block\|item\|b64>` | Материал блока, предмета или Base64 предмета |
| `/bpa bypass locked quests <игрок>` | Разблокировать недели игроку |
| `/bpa open <игрок>` | Открыть главное меню игроку |

Игрок должен хотя бы раз зайти на сервер. Валюта, почта и лоты сохраняются при смене сезона. Сброс отдельного квеста позволяет снова получить его награду. Бустеры суммируются, цель — `all`, ID задания или ключ `week-1:id`/`daily:id`. Процент от 0 до 10000. Premium даёт отдельную валютную награду каждого уровня; её можно забрать после покупки premium, даже если бесплатная уже получена.

## Задания и хранение

В `config.yml`: `quests.daily.<id>` и `quests.weeks.<номер>.<id>`. Типы: BREAK, PLACE, KILL, FISH, CRAFT. `material` — имя Material, для KILL — EntityType, `ANY` подходит всем. Для FISH используйте ANY. CRAFT считает обычные одиночные операции, массовый Shift-крафт не учитывается. Creative и Spectator не учитываются. Защита от фарма повторной установкой/ломанием блоков не предусмотрена: выбирайте задания с учётом правил сервера.

Неделя 1 доступна сразу; следующая открывается через 7 суток после начала сезона. Ежедневные задания сбрасываются по UTC в 00:00, состав берётся из конфигурации. Редактор создаёт ежедневные и недельные задания, меняет цель, опыт, валюту, тип и материал. Для материала предмета возьмите его в руку; имена сущностей KILL задаются в конфигурации. Номер недели для создания задаётся в action кнопки `[create] <номер>`. Удаление заданий выполняется в конфигурации. Параметры опыта уровня и аукциона задаются в `config.yml`.

Данные находятся в `plugins/GlowBattlePass/battlepass.db`, рабочий набор загружается в память. Изменения сохраняются транзакционным снимком SQLite с WAL и synchronous FULL; ошибка записи откатывает рабочий снимок. Не редактируйте БД при работающем сервере. Для копирования остановите сервер либо используйте штатный SQLite backup с учётом WAL. Снимки сохраняются синхронно; для очень больших серверов нужна отдельная оптимизация хранения.

Покупка атомарно изменяет балансы, лот и почту внутри SQLite. Для выставления и получения предметов используется журнал передачи в SQLite и временная PDC-метка предмета с сохранением playerdata. Незавершённые операции восстанавливаются при входе игрока. Общей транзакции между playerdata и SQLite нет; сценарии аварийного завершения и вмешательство других плагинов требуют отдельной проверки на тестовом сервере. При ошибке восстановления перемещение предметов игроком блокируется до устранения ошибки.

## Меню

Все файлы меню находятся именно в `plugins/GlowBattlePass/memus`. Размер — кратный 9 от 9 до 54. Секция `items` содержит элементы с `slot`, `material`, `name`, `lore`, `left_click_action`, `right_click_action`. Поддерживаются `&a` и RGB `&#aabbcc`, подстановки `{player}`, `{tier}`, `{balance}`. Динамические списки используют верхние ряды, последний ряд оставлен для управления.

Действия: `[message] текст`, `[player] команда`, `[console] команда`, `[open] меню`, `[close]`, `[sound] SOUND_NAME`, `[mail]`. В динамических списках также используются `[buy] UUID`, `[cancel] UUID`, `[reward] уровень`, `[auction] страница`, `[edit] индекс`, `[adjust] индекс поле шаг`. Console-actions выполняются с правами консоли: доступ к YAML должен быть только у администрации. Пример:

```yaml
items:
  example:
    slot: 22
    material: EMERALD
    name: '&#55ff99Баланс: {balance}'
    left_click_action:
      - '[message] &aВаш баланс: {balance}'
    right_click_action:
      - '[player] bp stats'
```

## PlaceholderAPI

`%glowbattlepass_balance%`, `%glowbattlepass_tier%`, `%glowbattlepass_experience%`, `%glowbattlepass_quests%`, `%glowbattlepass_pass%`.

## Прокси

`/bpa sync daily quests` требует игрока онлайн и BungeeCord plugin messaging. На Velocity включите совместимость BungeeCord plugin messages. Команда рассылает текущую UTC-дату, получатели обновляют день без повторного сброса. Доставку выключенным серверам канал не гарантирует; они обновляют дату при запуске. Принудительный повторный сброс текущего дня командой refresh локальный. Валюта, аукцион и прогресс между серверами не объединяются; каждому серверу нужна собственная БД. Не подключайте несколько процессов к одному файлу.

## Проверки перед выпуском

В `StorageTest` подготовлены проверки сохранения между открытиями SQLite и отката неуспешной транзакции. В `DomainTest` подготовлены проверки недостаточного баланса, переполнения, отрицательных сумм, повторной покупки, истечения и снятия лотов, бустеров, недель и сброса сезона. Они не запускались. После сборки проверьте на тестовом сервере продажу предметов с метаданными, покупку двумя игроками, почту с полным инвентарём, повторный клик, перезапуск и восстановление, права доступа, меню с Shift/drag/цифровыми клавишами, задания и необязательную PlaceholderAPI. Проверяйте 1.16.5 и каждую новую целевую версию отдельно.
